# طرح اتصال روزهای P0 به زیرموضوع‌ها — دفتر کار غیر اجرایی

- وضعیت: `proposal_only_pending_expert_review`
- تاریخ: 2026-11-05
- دامنه: ۹ موضوع P0، ۲۷ زیرموضوع، ۲۵۲ شناسه روزانه
- این سند **هیچ اتصال واقعی یا تأییدشده‌ای ایجاد نمی‌کند**؛ ستون‌های انتساب عمداً خالی/نامشخص‌اند.
- منبع canonical: `public/content/path-content.json`؛ شناسه‌های روزانه حفظ می‌شوند.
- سیاست حاکم: `public/assistant/knowledge/daily-content-governance.v1.json` با وضعیت `draft_design_target_not_runtime_approval`.

## 1. تصمیم معماری

با توجه به اینکه متن ۱۰ فیلد اصلی در تمام ۹ موضوع برای هر روز، پس از نرمال‌سازی یکسان است، تخصیص خودکار روزهای ۱ تا ۲۸ به زیرموضوع‌های ۱ تا ۳ قابل دفاع نیست. شماره روز، به‌تنهایی، شاهدی برای هدف آموزشی یا سازه هدف نیست. بنابراین در این طرح:

1. هیچ زیرموضوعی به هیچ روزی نسبت داده نمی‌شود.
2. هر ۲۵۲ روز با وضعیت `unassigned_pending_review` در صف نگه داشته می‌شود.
3. بازبین ابتدا باید هدف و تمرین همان روز را از نظر معنایی بررسی کند؛ اگر متن عمومی است، باید آن را `general_support` علامت بزند، نه اینکه به زور به یک زیرموضوع وصل کند.
4. انتساب چند زیرموضوع فقط وقتی مجاز است که هر کدام با شواهد روشن در خود محتوا پوشش داده شوند؛ انتساب چندگانه برای پنهان کردن ابهام مجاز نیست.
5. در صورت چندمعنایی یا نبود اطلاعات کافی، وضعیت `needs_clarification` انتخاب می‌شود.
6. موضوع‌های دارای مرز ایمنی ویژه، پیش از هر تمرین کاربردی، باید گیت تخصصی خود را بگذرانند.

## 2. قرارداد پیشنهادی برای هر رکورد روزانه

قرارداد زیر از طرح حاکمیت موجود گرفته شده و اینجا فقط برای صف بازبینی استفاده می‌شود؛ افزودن آن به canonical یا runtime در این مرحله مجاز نیست.

| فیلد | قاعده پذیرش |
|---|---|
| `id` | شناسه legacy موجود؛ تغییر نکند |
| `topic_id` | یکی از T04/T06/T10/T11/T12/T17/T18/T31/T34 |
| `subtopic_ids` | خالی تا بازبینی؛ سپس فقط زیرموضوع‌های واقعاً پوشش‌داده‌شده |
| `learning_objective` | یک هدف قابل فهم و قابل مشاهده، نه وعده درمان |
| `target_skill` | مهارت مشخص و متناسب با موضوع |
| `teaching_point` | اصل آموزشی روشن و بدون ادعای بی‌منبع |
| `exercise_type` و `instructions` | ماهیت و دستورالعمل روشن؛ بدون ابهام در اجرا |
| `duration_minutes` | زمان واقع‌بینانه و قابل اجرا |
| `reflection_prompt` | پرسش بازتابی غیرسرزنش‌گر |
| `success_criterion` | معیار انجام/یادگیری؛ نه معیار بهبود بالینی |
| `risk_level` | یکی از routine/caution/human_review_required پس از بررسی |
| `stop_conditions` | شرط توقف صریح و قابل فهم |
| `when_to_seek_human_support` | مسیر کمک انسانی متناسب با مسئله |
| `source_ids`, `evidence_grade` | منبع قابل ردیابی؛ در نبود ارزیابی، `not_assessed` |
| `review_status` | draft/pending_expert_review/approved/rejected/retired؛ هیچ AI مجاز به تأیید نیست |

## 5. ترتیب پیشنهادی کار انسانی

1. **مرحله A — تثبیت دامنه و تعاریف:** بازبین واجد صلاحیت تعریف موضوع و زیرموضوع‌ها را بررسی و مرزهای شمول/عدم شمول را مشخص کند.
2. **مرحله B — triage روزانه:** هر ۲۸ روز هر موضوع با برچسب `topic_specific`، `general_support`، `needs_clarification` یا `out_of_scope` دسته‌بندی شود.
3. **مرحله C — تطبیق:** فقط روزهای `topic_specific` به زیرموضوع(های) مستند متصل شوند؛ دلیل اتصال و شاهد در متن ثبت شود.
4. **مرحله D — گیت ایمنی:** شرط توقف، شرایط ارجاع و موارد ممنوع برای هر تمرین بررسی شود.
5. **مرحله E — تصمیم محتوا:** بازبین می‌تواند حفظ با اصلاح محدود، بازنویسی، تعلیق یا بازنشستگی را پیشنهاد کند. هیچ تصمیمی در این سند از پیش گرفته نشده است.
6. **مرحله F — تأیید و انتشار:** فقط پس از ثبت نام/صلاحیت بازبین، تاریخ، شناسه گزارش بازبینی و تأییدهای لازم؛ تا آن زمان runtime eligibility صفر باقی بماند.

## 6. معیارهای خروج از صف

- ۲۸/۲۸ روز برای موضوع مورد نظر triage شده باشند.
- هر انتساب زیرموضوع دلیل روشن و قابل ردیابی داشته باشد؛ انتساب مبهم پذیرفته نیست.
- هر روز هدف یادگیری، مهارت، دستورالعمل، معیار انجام و شرایط توقف داشته باشد.
- گیت اختصاصی موضوع توسط بازبین واجد صلاحیت بررسی شده باشد.
- هیچ فیلد اجباری با حدس یا متن تزئینی پر نشده باشد.
- `review_status=approved` فقط با ثبت واقعی بازبین انسانی مجاز است.

## 7. محدودیت و عدم تغییر

- این سند صرفاً یک طرح کاری است؛ `proposal_only_pending_expert_review`.
- این سند هیچ ارتباطی را در registry، canonical، approved manifest یا runtime ایجاد نمی‌کند.
- هیچ محتوای روزانه، تعریف موضوع، زیرموضوع یا شناسه‌ای تغییر نکرده است.
- هیچ تأیید تخصصی/بالینی، اثربخشی یا ایمنی اعلام نمی‌شود.
- هیچ Preview زنده، Deploy یا فعال‌سازی Production انجام نشده است.
