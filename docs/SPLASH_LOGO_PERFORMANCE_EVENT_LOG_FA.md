# دفتر اجرایی بهینه‌سازی لوگوی صفحه آغازین

> این سند مرجع ماندگار پروژه است. ادامه کار باید از آخرین commit شاخه اجرایی بازیابی شود.

## هدف
کاهش زمان نمایش لوگوی صفحه آغازین و حذف وابستگی آماده‌شدن برنامه به دریافت/Decode تصویر لوگو، بدون تغییر در ظاهر و عملکرد سایر بخش‌ها.

## محدوده و قواعد
- مخزن: `H3269/Maseer28-V1`
- شاخه مبنا: `main`
- شاخه اجرایی: `perf/fast-reliable-splash-logo`
- تغییرات فقط در صفحه آغازین، خط ساخت تصویر سبک، آزمون‌های مرتبط و همین دفتر ثبت انجام می‌شود.
- `main` تا تأیید جداگانه کاربر تغییر نمی‌کند.
- انتشار تلگرام/بله خارج از این کار است و مجوز جداگانه می‌خواهد.
- موفقیت CI جای آزمون واقعی روی گوشی اندرویدی کاربر را نمی‌گیرد.

## خط مبنای مشاهده‌شده در main
- تصویر اصلی `public/assets/Logo m24.webp` برابر 428,260 بایت است، در حالی که در صفحه آغازین با ابعاد 174×174 پیکسل نمایش داده می‌شود.
- تصویر در HTML اولیه و دوباره در React بارگذاری/نمایش داده می‌شد.
- انیمیشن آشکارسازی تصویر در HTML اولیه 950 میلی‌ثانیه و در CSS صفحه React نیز 950 میلی‌ثانیه بود؛ این انتقال می‌توانست انیمیشن را دوباره آغاز کند.
- React تا Decode تصویر و سپس یک تایمر اضافی 1,100 میلی‌ثانیه‌ای صبر می‌کرد.
- خطای تصویر می‌توانست کل صفحه را در وضعیت خطا نگه دارد و کاربر را به تازه‌سازی دستی وابسته کند.
- preload با اولویت بالا از قبل وجود داشت؛ بنابراین مشکل فقط اولویت درخواست نبود.

## اصلاحات اعمال‌شده روی شاخه آزمایشی
1. افزودن تولیدکننده `scripts/prepare-splash-logo.mjs` برای ساخت نسخه WebP با ابعاد 192×192 و کیفیت 58 از تصویر اصلی؛ بودجه خروجی حداکثر 40 KiB است. تصویر اصلی حذف یا بازنویسی نمی‌شود.
2. افزودن تولید تصویر سبک به چرخه `prebuild` تا فایل به‌صورت تکرارپذیر در هر build ساخته شود.
3. تغییر preload و هر دو محل نمایش لوگو به `assets/splash-logo.webp`.
4. نمایش فوری لوگو و متن؛ حذف انیمیشن reveal و mask که تصویر را در ابتدا پنهان می‌کرد.
5. حذف وابستگی رندر برنامه به آماده‌شدن یا Decode لوگو و حذف مکث مصنوعی 1,100 میلی‌ثانیه‌ای.
6. در صورت شکست درخواست تصویر سبک، React یک بار به تصویر جایگزین موجود `assets/logo.png` رجوع می‌کند؛ شکست تصویر دیگر مانع بازشدن برنامه نیست.
7. حفظ خطای واقعی دریافت محتوای برنامه و دکمه تلاش دوباره؛ اصلاح لوگو نباید مسیر بازیابی خطای محتوای اصلی را حذف کند.
8. بازنویسی آزمون‌های startup برای سنجش نمایش فوری لوگو و حذف انتظار انیمیشن.

## معیارهای پذیرش
- تولیدکننده در build اجرا شود و خروجی از 40 KiB بیشتر نباشد.
- لوگوی سبک در HTML اولیه preload شود و ابعاد نمایشی 174×174 حفظ شود.
- CSS تصویر را با opacity صفر، clip-path بسته یا انیمیشن پنهان نکند.
- React برای نمایش برنامه منتظر Decode لوگو یا تایمر اضافی نباشد.
- شکست لوگو مانع دسترسی به برنامه نشود؛ شکست محتوای برنامه همچنان پیام خطا و امکان تلاش دوباره داشته باشد.
- تست‌های واحد، آزمون مرورگر، build و کل CI سبز باشند.
- زمان و رفتار نهایی روی گوشی واقعی کاربر جداگانه تأیید شود.
