# طرح نمونه‌سازی دستیار نوشتاری کاملاً محلی

**تاریخ:** 2026-11-06  
**وضعیت:** طرح اجرایی نمونه‌سازی؛ هنوز runtime یا مدل به اپ اضافه نشده است.  
**مخزن/شاخه:** H3269/Maseer28-V1 / main

## 1. تصمیم دامنه

از این مرحله به بعد، مأموریت فعال دستیار فقط مکالمه نوشتاری است:
- ورودی و خروجی فقط متن؛
- استنتاج مدل زبانی روی خود دستگاه؛
- عدم ارسال prompt، تاریخچه یا زمینه مکالمه به سرویس هوش مصنوعی ابری؛
- حفظ کنترل‌های ایمنی فعلی و تقدم آن‌ها بر مدل؛
- استفاده از همان پنجره، کادر نوشتار و دکمه ارسال موجود.

ASR، TTS، میکروفون، پخش صدا و هرگونه رابط صوتی از دامنه فعال خارج‌اند. این تصمیم هیچ تغییری در UI ایجاد نمی‌کند. هیچ صفحه، متن، کادر، پنجره، ورودی یا کنترل جدیدی اضافه نخواهد شد.

## 2. حکم امکان‌پذیری فعلی

**حکم: از نظر فنی شدنی، اما هنوز برای ناوگان واقعی تلگرام و بله اثبات نشده و نمی‌توان سازگاری همگانی را وعده داد.**

شواهد:
- Transformers.js اجرای مدل‌های NLP و text generation را در مرورگر، بدون سرور، از طریق ONNX Runtime پشتیبانی می‌کند؛ مسیر پیش‌فرض CPU/WASM و مسیر WebGPU اختیاری است. مستند رسمی استفاده از مدل‌های quantized مانند q4 را برای محیط محدود توصیه می‌کند.
- ONNX Runtime Web، WASM/CPU را در جدول سازگاری برای Chrome Android فهرست می‌کند؛ این سند، سازگاری WebView داخلی Telegram یا Bale را تضمین نمی‌کند.
- مستند ONNX Runtime برای مدل‌های بزرگ محدودیت‌های واقعی ArrayBuffer، حافظه WASM و روش cache کردن مدل را توضیح می‌دهد. بنابراین مدل بزرگ و حافظه آزاد دستگاه، ریسک اصلی است.
- WebLLM به WebGPU وابسته است و برای مسیر پایه همه دستگاه‌ها مناسب فرض نمی‌شود؛ می‌تواند فقط مسیر اختیاری دستگاه‌های واجد شرایط باشد.

## 3. مسیر فنی پیشنهادی برای اثبات

### مسیر پایه مورد آزمون
Transformers.js + ONNX Runtime Web با WASM/CPU و مدل زبانی instruction کوچک و quantized. این صرفاً نامزد prototype است، نه انتخاب نهایی.

### مسیر شتاب‌دار اختیاری
در صورت وجود WebGPU و تأیید عملی در میزبان واقعی، مدل/runtime سازگار با WebGPU سنجیده شود. نبود WebGPU نباید کل دستیار نوشتاری را از کار بیندازد.

### مسیر کم‌منبع
اگر مدل مولد فارسی روی CPU دستگاهی کند، ناپایدار یا بیش از حد پرمصرف باشد، آن دستگاه نباید پاسخ مولدِ ساختگی یا ابری دریافت کند. باید قابلیت محلیِ محدودتر و صادقانه، با همان موتور/دانش فعلی، حفظ شود؛ این fallback به معنی LLM نیست.

## 4. معماری مورد نیاز

1. **Text runtime adapter:** قرارداد مستقل برای load، generate، cancel، dispose و گزارش وضعیت؛ وابستگی مستقیم UI به کتابخانه مدل ممنوع.
2. **Worker isolation:** اجرای inference خارج از thread رابط تا حد امکان؛ توقف و آزادسازی منابع در تغییر صفحه/بسته‌شدن میزبان.
3. **Model lifecycle:** دانلود اولیه صریح و قابل‌فهم با استفاده از کنترل‌های فعلی، اعتبارسنجی فایل، cache پایدار، تشخیص فایل ناقص، پاک‌سازی و بازیابی.
4. **Offline boundary:** پس از دانلود و آماده‌سازی، inference بدون اینترنت؛ هیچ fallback ابری مجاز نیست.
5. **Safety orchestration:** قواعد ایمنی فعلی پیش از inference اجرا شوند؛ مدل حق لغو یا تضعیف handoff/clarification موجود را ندارد. خروجی مدل باید از کنترل‌های خروجی عبور کند.
6. **Context boundary:** ابتدا فقط پیام جاری و زمینه حداقلیِ مجاز؛ اتصال دانش کل اپ و داده‌های شخصی در مرحله مستقل و فقط‌خواندنی. داده حساس پروفایل نباید خودکار به prompt تزریق شود.
7. **Memory:** در این prototype حافظه بلندمدت یا ذخیره transcript اضافه نشود؛ فقط تاریخچه کوتاهِ موقت نشست و با حد مشخص.
8. **No UI expansion:** از textarea، send button، transcript و dialog فعلی استفاده شود. اگر وضعیت بارگیری/خطا/لغو با کنترل‌های فعلی قابل نمایش نباشد، کار متوقف و محدودیت گزارش شود.

## 5. آزمون‌های پذیرش نمونه‌سازی

### آزمون‌های رومیزی
- مدل واقعاً محلی بارگیری و اجرا شود؛ mock یا پاسخ ثابت قابل قبول نیست.
- prompt و history در مسیر inference باقی بمانند و هیچ endpoint ابری فراخوانی نشود.
- پاسخ فارسی، دستورپذیری، حفظ زمینه چندمرحله‌ای، پاسخ به پرسش عمومی، عدم قطعیت و امتناع در نبود دانش ارزیابی شوند.
- آزمون‌های موجود ایمنی و routing بدون افت عبور کنند.
- مدل در Worker اجرا شود و thread رابط هنگام inference قفل نشود.
- قطع شبکه پس از دانلود، اجرای inference را مختل نکند.

### آزمون‌های میدانی
هر میزبان جداگانه: Chrome Android، Telegram Android، Bale Android. در هر میزبان دستگاه کم‌منبع، میان‌رده و پرچم‌دار باید پوشش داده شود. معیارها:
- حجم دانلود و فضای ذخیره؛
- زمان بارگیری اولیه و زمان اولین توکن؛
- سرعت تولید توکن؛
- RAM اوج و crash/reload؛
- پایداری cache پس از بستن/بازکردن میزبان؛
- اجرای کامل در حالت آفلاین؛
- capture شبکه برای اثبات عدم خروج prompt/history/context؛
- رفتار پس‌زمینه، تغییر صفحه، لغو و کمبود حافظه.

آزمون Chrome به‌تنهایی تأیید Telegram یا Bale نیست. دستگاه Samsung SM-A307FN با Android 11 فقط یکی از نمونه‌هاست، نه معیار کل ناوگان.

## 6. دروازه تصمیم

نمونه‌سازی فقط وقتی موفق تلقی می‌شود که:
- inference واقعی و فارسی روی دستگاه انجام شود؛
- حداقل یک مسیر WASM/CPU و هر مسیر شتاب‌دارِ ادعاشده جداگانه اندازه‌گیری شود؛
- هیچ داده مکالمه به AI ابری ارسال نشود؛
- معیارهای RAM/سرعت/پایداری برای هر میزبان و طبقه دستگاه ثبت شوند؛
- آزمون ایمنی موجود بدون regression عبور کند.

اگر مدل روی دستگاه کم‌منبع قابل‌قبول نباشد، دامنه سخت‌افزاری پنهانی محدود نمی‌شود؛ محدودیت همان ترکیب دستگاه/میزبان مستند و fallback صادقانه تعریف می‌شود.

## 8. مواردی که هنوز اثبات نشده‌اند

- مدل فارسی مشخص و مجوز استفاده تجاری/توزیع آن؛
- کیفیت مکالمه طبیعی فارسی در برابر مجموعه ارزیابی مستقل؛
- سرعت و RAM در دستگاه‌های واقعی؛
- کارکرد runtime در WebView تلگرام و بله؛
- ماندگاری cache مدل و اجرای آفلاین در هر دو میزبان؛
- امکان انجام همه حالت‌های بارگیری/خطا با UI موجود.

تا پیش از عبور از این موارد، هیچ مدل یا runtime به محصول اضافه و هیچ قابلیت LLM محلی آماده اعلام نمی‌شود.
