## ۱. تصمیم نسخه نخست

از Worker موجود استفاده می‌شود؛ Worker جدیدی ساخته نمی‌شود. کد منبع در `workers/assistant-api` نگهداری می‌شود تا از ویرایش دستی کد در Dashboard و اختلاف نسخه جلوگیری شود.

نسخه نخست عمداً هیچ مدل زبانی، ذخیره‌سازی مکالمه، حافظه پایدار، اتصال دیتابیس یا ارسال داده به ارائه‌دهنده بیرونی ندارد. endpoint مکالمه تا عبور از دروازه‌های حریم خصوصی و ایمنی، پاسخ `503 assistant_not_configured` می‌دهد و بدنه درخواست را نمی‌خواند.

## ۲. قرارداد endpointها

### `GET /health`

- پاسخ ۲۰۰ در صورت اجرای Worker.
- اعلام `assistantEnabled: false` و `providerConfigured: false`.
- فاقد داده کاربر و بدون وابستگی به provider.

### `POST /v1/assistant/turn`

- در نسخه فعلی همیشه پاسخ ۵۰۳ می‌دهد.
- بدنه درخواست خوانده، پردازش، ذخیره یا در پاسخ بازتاب داده نمی‌شود.
- فعال‌سازی این endpoint منوط به رضایت معتبر و تفکیک‌شده، سیاست نگهداری/حذف، کنترل ایمنی مستقل، اعتبارسنجی schema و انتخاب provider است.

### CORS و هدرها

- مبدأها فقط از allowlist دقیق `ALLOWED_ORIGINS` پذیرفته می‌شوند.
- wildcard و ارسال credential در CORS مجاز نیست.
- پاسخ‌ها `no-store` و دارای هدرهای پایه امنیتی‌اند.
- ثبت متن خام درخواست در log در این اسکلت پیاده‌سازی نشده است.

## ۳. پیکربندی Cloudflare

فایل `wrangler.toml` به Worker موجود اشاره می‌کند؛ این فایل به‌تنهایی هیچ چیزی را در Cloudflare منتشر یا تغییر نمی‌دهد. قبل از هر انتشار باید:
1. نام Worker و حساب/محیط هدف دوباره تأیید شود.
2. allowlist دقیق origin از روی دامنه واقعی اپ تعیین شود.
3. متغیرها و secrets از Dashboard تنظیم شوند؛ هیچ secret در Git قرار نگیرد.
4. تست‌های محلی و CI و تست smoke در محیط غیرعملیاتی موفق باشند.
5. تأیید صریح مالک برای Deploy دریافت شود.

## ۴. دروازه‌های لازم پیش از فعال‌سازی مدل

1. تکمیل ارزیابی جریان داده و مدل تهدید Backend.
2. تعیین بازار هدف، پردازشگر، منطقه پردازش، دسته داده، مدت نگهداری و روش پس‌گرفتن رضایت.
3. پیاده‌سازی رضایت مستقل برای پردازش ابری و داده حساس؛ پیش‌فرض همه گزینه‌ها خاموش.
4. احراز هویت/نشست و محدودیت نرخ در سمت سرور.
5. موتور ایمنی مستقل از LLM و آزمون red-team فارسی برای خطر فوری، خودآسیبی، خشونت و موارد خارج از دامنه.
6. آداپتور provider-neutral با timeout، سقف هزینه/توکن، مدیریت خطا و عدم ثبت متن خام.
7. اعتبارسنجی خروجی ساختاریافته و تطبیق فقط با شناسه‌های واقعی ۳۴ موضوع؛ محتوای تأییدنشده نباید پیشنهاد شود.
8. سازوکار حذف داده و آزمون اثباتی آن.

تا زمان بسته‌شدن این موارد، استفاده از داده واقعی کاربران یا ارسال متن روان‌شناختی به مدل بیرونی ممنوع است.

## ۵. آزمون‌ها

آزمون‌های `tests/assistantWorker.test.js` رفتار health، غیرفعال‌بودن endpoint مکالمه، عدم بازتاب متن ارسالی، CORS دقیق، رد origin ناشناخته و مسیرهای نامعتبر را پوشش می‌دهند. اجرای موفق آزمون‌ها باید از خروجی Node test runner و CI ثبت شود؛ وجود فایل تست به‌تنهایی اثبات عبور نیست.
