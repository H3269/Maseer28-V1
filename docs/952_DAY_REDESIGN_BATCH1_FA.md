## زیرساخت آزمایشی رضایت و شخصی‌سازی — هنوز متصل نشده

این شاخه چند ماژول آزمایشی برای رضایت محلی، ذخیره ترجیحات غیرحساس، ساخت context محدود و قالب‌بندی پرسش‌ها اضافه می‌کند؛ اما این اجزا در مسیر فعال محصول به هم متصل نشده‌اند:

- `PersonalizationSettings.jsx` هنوز در مسیرهای UI فعلی import یا نمایش داده نمی‌شود.
- `AssessmentAssistant.jsx` در رابط فعال نصب نشده است؛ لانچر سراسری فعلی همچنان از `GlobalAssistantLauncher` و موتور مستقل خودش استفاده می‌کند.
- `assistantPreferences.js` و `assistantContext.v1.js` در جریان فعال لانچر سراسری مصرف نمی‌شوند.
- قرارداد فعلی `createAssessmentSession` و `submitAssessmentAnswer` نیز context و consent را دریافت/اعتبارسنجی و در session نگهداری نمی‌کند؛ ارسال آرگومان اضافی از UI به‌تنهایی اتصال محسوب نمی‌شود.
- `assessmentLanguageContext.v1.js` یک ماژول آزمایشی با آزمون‌های مستقل است و در router فعال فراخوانی نمی‌شود.
- `assessmentTopicRuleRegistry.v1.js` رجیستری پژوهشی/نسخه‌دار است؛ router فعال هنوز آرایه مستقل `TOPIC_RULES` را مصرف می‌کند. رجیستری در این نسخه منبع واحد قواعد runtime نیست.

بنابراین این ماژول‌ها در وضعیت فعلی هیچ تغییر تضمین‌شده‌ای در رفتار دستیار قابل مشاهده کاربر ایجاد نمی‌کنند. رضایت محلی نیز مجوز پردازش ابری یا داده حساس نیست. هرگونه اتصال آینده نیازمند مسیر UI روشن، رضایت مستقل و قابل لغو، اعتبارسنجی در هر نوبت، انقضا/پاک‌سازی context، آزمون یکپارچه و تضمین عدم تغییر پرسش‌های ایمنی است.

این اتصال هنوز شخصی‌سازی معنایی پاسخ آزاد، انتخاب مداخله، حافظه گفتگویی یا یادگیری از سابقه روان‌شناختی نیست. سرعت پرسش‌ها به‌دلیل ترتیب ثابت ایمنی، گروهی نمی‌شود. تنظیم زبان نیز هنوز به ترجمه کامل موتور متصل نیست. این قابلیت‌ها نباید به‌عنوان تکمیل‌شده معرفی شوند.
