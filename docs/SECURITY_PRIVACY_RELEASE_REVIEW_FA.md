**وضعیت:** بررسی ایستا و مقدماتی؛ بدون آزمون نفوذ یا اجرای نسخه  
**مخزن:** H3269/Maseer28-V1  
**شاخه بررسی:** main  
**تاریخ بررسی:** 2026-11-01

> این سند ارزیابی حقوقی یا گواهی امنیتی نیست. یافته‌ها فقط به فایل‌ها و رفتار قابل مشاهده در مخزن محدودند.

## ۱. خلاصه مدیریتی

سه حوزه قبل از اتصال دستیار مکالمه‌ای باید تعیین تکلیف شوند:

1. داده‌های حساس پروفایل و مسیر در مرورگر ذخیره می‌شوند.
2. برنامه فعلی build و deploy خودکار دارد، اما در package.json اسکریپت آزمون خودکار مشاهده نشد.
3. workflow انتشار نسخه تلگرام می‌تواند ref انتخاب‌شده هنگام اجرای دستی را checkout کند و خروجی را به مخزن جداگانه H3269/Maseer28 روی main push کند؛ بنابراین کنترل اینکه فقط نسخه واقعاً آزموده‌شده منتشر شود باید تقویت شود.

هیچ آسیب‌پذیری قابل بهره‌برداری با آزمون پویا اثبات نشده است. این موارد ریسک طراحی و کنترل هستند و باید با آزمون فنی تکمیل شوند.

## ۲. موجودی داده‌ای قابل مشاهده

### داده‌های پروفایل
در journeyStore.js فیلدهای زیر از وضعیت مسیر به پروفایل جداگانه منتقل می‌شوند:
- نام، سن، جنسیت، شماره تلفن
- وضعیت پزشکی و توضیح پزشکی
- وضعیت مصرف دارو و ریسک مرتبط با دارو

همچنین اطلاعات مسئله، مدت، هدف و کد مسیر در profileData ذخیره می‌شوند.

### داده‌های مسیر
- پاسخ‌های متنی روزانه تا ۳۰۰۰ نویسه
- بازخورد متنی تا ۱۰۰۰ نویسه
- نمره‌ها و پاسخ‌های ارزیابی
- شناسه تمرین، تاریخ به‌روزرسانی و پیشنهاد کتاب/صفحه
- آرشیو مسیر و گزارش پایانی

### محل ذخیره مشاهده‌شده
- `maseer28_state` در localStorage
- `maseer28_user_profile_v1` در localStorage
- کتاب‌ها و نسخه‌ها در IndexedDB

**نتیجه:** پاسخ‌های آزاد روزانه ممکن است حاوی اطلاعات سلامت، روابط، آسیب یا بحران باشند؛ حتی اگر فرم از کاربر چنین اطلاعاتی را صریحاً نخواهد. باید آن‌ها را داده حساس بالقوه در نظر گرفت.

## ۴. نکات انتشار

### GitHub Pages
`.github/workflows/deploy.yml` با push روی main و اجرای دستی فعال می‌شود:
- Node 22
- npm ci
- npm run build با base path
- آپلود dist و deploy روی GitHub Pages

در package.json فعلی فقط dev/build/preview وجود دارد؛ test/lint/typecheck تعریف نشده‌اند. بنابراین workflow انتشار صفحات در وضعیت قابل مشاهده، آزمون خودکار رفتاری را اجرا نمی‌کند.

### انتشار نسخه تلگرام
`.github/workflows/publish-tested-version.yml`:
- با workflow_dispatch اجرا می‌شود.
- ورودی publish باید روی publish قرار گیرد.
- ref اجرای workflow را checkout می‌کند.
- TEST_MODE را false و TIME_LOCK_ENABLED را true می‌کند.
- npm ci و npm run build اجرا می‌کند.
- با TELEGRAM_REPO_TOKEN به مخزن H3269/Maseer28 روی main push می‌کند.
- خروجی dist را با rsync --delete منتشر می‌کند.

**ریسک کنترل انتشار:** توضیح workflow می‌گوید «نسخه تست‌شده»، اما در خود فایل سازوکار قابل مشاهده‌ای که ref را فقط به main یا یک tag تأییدشده محدود کند وجود ندارد. اجرای دستی از ref دیگر ممکن است به انتشار همان ref منجر شود. این را باید با branch/tag allowlist و approval کنترل کرد.

## ۸. نتیجه اجرای واقعی ممیزی وابستگی‌ها (2026-11-01)

در GitHub Actions پس از `npm ci`، فرمان `npm audit --audit-level=high` اجرا شد و job را با وضعیت failure متوقف کرد. خروجی دقیق:

- ۳ advisory: دو High و یک Moderate.
- `source-map-js 1.0.0–1.2.1` با شدت High، شناسه `GHSA-68fv-2mgg-jv7q`؛ زنجیره فعلی از `postcss 8.5.28` و بازه وابستگی `^1.2.1` وارد lockfile می‌شود.
- `esbuild <=0.24.2` با شدت Moderate، شناسه `GHSA-67mh-4wv8-2f99`؛ در زنجیره Vite فعلی (`vite 5.4.21`) قرار دارد.
- گزارش npm برای رفع مورد source-map-js، `npm audit fix` را پیشنهاد می‌کند؛ برای زنجیره Vite/esbuild، `npm audit fix --force` را پیشنهاد می‌کند که Vite 8.3.5 و تغییر ناسازگار major به همراه دارد.

**تصمیم:** ارتقای کورکورانه یا `--force` اجرا نشد. Dependabot برای npm و GitHub Actions هفتگی فعال شد تا به‌روزرسانی‌ها در PR جداگانه بررسی شوند. ممیزی امنیتی در CI عمداً شکست را گزارش می‌کند؛ اعتبارسنجی محتوا و build با وجود آن ادامه می‌یابند و هر دو موفق شدند.

### تفسیر ریسک

- آسیب‌پذیری esbuild که در advisory گزارش شده مربوط به امکان ارسال درخواست از یک وب‌سایت به dev server و خواندن پاسخ است؛ این موضوع به شرایط اجرای dev server وابسته است و نباید بدون بررسی محیط استقرار، آن را آسیب‌پذیری قطعی نسخه production معرفی کرد.
- مورد source-map-js با شدت High گزارش شده است؛ زنجیره وابستگی و مسیر قابل‌دسترسی در build باید پس از ارتقا دوباره بررسی شود.
- این گزارش جایگزین آزمون exploitability، بررسی سرور میزبانی یا بازبینی lockfile پس از رفع نیست.

## ۹. نتیجه CI در PR شماره ۲

در اجرای شماره ۷:
- `npm ci`: موفق
- `npm audit --audit-level=high`: ناموفق، به دلیل advisoryهای فوق
- `npm run validate:content`: موفق
- `npm run build`: موفق (Vite 5.4.21؛ ۴۵ ماژول تبدیل شدند)

بنابراین build سالم است، اما gate امنیت وابستگی‌ها هنوز قرمز است. این دو نتیجه نباید با هم خلط شوند.
