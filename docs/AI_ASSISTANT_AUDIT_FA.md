# ممیزی فنی اولیه مسیر۲۸ برای توسعه دستیار هوشمند

**وضعیت:** ممیزی مقدماتی، فقط خواندنی  
**مخزن:** `H3269/Maseer28-V1`  
**شاخه مبنا:** `main`  
**محدوده:** فایل‌های قابل بازیابی از مخزن در این مرحله  
**مهم:** این سند ممیزی کامل امنیتی، بالینی یا محتوایی نیست.

## ۱. یافته‌های تأییدشده

| حوزه | یافته | پیامد |
|---|---|---|
| رابط | React 18.3.1 و React DOM | امکان توسعه تدریجی در رابط فعلی |
| ساخت | Vite 5.4.x | خروجی فعلی برای استقرار استاتیک طراحی شده است |
| وابستگی‌ها | در package.json فقط React/React DOM و ابزار Vite دیده شد | وابستگی یا SDK شناخته‌شده AI در manifest فعلی دیده نشد |
| مسیر | منطق مسیر در src/features/journey و جریان اصلی در src/App.jsx | هسته مسیر موجود است و باید حفظ شود |
| وضعیت کاربر | journeyStore از localStorage برای وضعیت و پروفایل استفاده می‌کند | داده روی همان مرورگر نگهداری می‌شود؛ همگام‌سازی بین دستگاهی در این کد اثبات نشده |
| کتابخانه | IndexedDB در libraryRepository استفاده می‌شود | ذخیره‌سازی کتاب‌ها از وضعیت مسیر جداست |
| محتوای دوره | App.jsx فایل public/content/path-content.json را دریافت می‌کند | محتوای آموزشی از منطق نمایش جدا شده است |
| ارزیابی | پنج پرسش مقیاس شروع و پنج پرسش پایانی در JourneyScreens.jsx | شاخص داخلی مسیر است؛ اعتبار ابزار بالینی از کد اثبات نمی‌شود |
| ایمنی | متن هشدار و ارجاع عمومی در JourneyScreens.jsx دیده شد | راهنمای ثابت، جایگزین تشخیص خطر در زمان مکالمه نیست |
| تنظیمات | APP_CONFIG در journeyStore شامل TEST_MODE=true و TIME_LOCK_ENABLED=false است | پیش از انتشار باید تصمیم محصولی و آزمون شود |

## ۲. محدودیت‌های مشاهده

- فایل `public/content/path-content.json` با ابزار فعلی قابل بازیابی نبود؛ بنابراین فهرست واقعی دسته‌ها، شمار روزها، ساختار تمرین‌ها و محتوای هر ۲۸ روز هنوز تأیید نشده است.
- README به چهار کتاب اشاره می‌کند، درحالی‌که جست‌وجوی اولیه در `library.seed.json` پنج ورودی کتاب نشان داد. باید فهرست و فایل‌های واقعی تطبیق داده شوند.
- نبود اتصال AI، Backend، احراز هویت یا رمزنگاری در فایل‌های بررسی‌شده به معنای اثبات نبود آن‌ها در تمام مخزن یا زیرساخت استقرار نیست. بررسی کامل فایل‌ها، تنظیمات استقرار و سرویس‌های بیرونی لازم است.
- این مرحله شامل اجرای build، آزمون نفوذ، بررسی وابستگی‌ها، بررسی مجوزهای محتوا یا ارزیابی بالینی نشده است.

## ۳. ریسک‌های اولویت‌دار

### P0 — پیش از ورود اطلاعات حساس به دستیار
1. ترسیم جریان داده از مرورگر تا هر سرویس بیرونی.
2. تعیین اینکه کدام داده‌ها واقعاً لازم‌اند؛ حذف پیش‌فرض داده‌های غیرضروری مانند شماره تماس از پردازش روان‌شناختی.
3. طراحی رضایت آگاهانه، هدف پردازش، مدت نگهداری، خروجی‌گرفتن و حذف داده.
4. عدم قرار دادن کلید مدل یا کلید محرمانه در کد سمت مرورگر.
5. طراحی کنترل دسترسی، رمزنگاری انتقال و ذخیره‌سازی، مدیریت نشست، ثبت رویدادهای امنیتی و سیاست پشتیبان‌گیری.
6. سیاست روشن برای داده‌های افراد زیر سن قانونی و داده‌های سلامت/روان‌شناختی.

### P1 — پیش از پایلوت
1. موتور ایمنی مستقل از مدل زبانی.
2. جلوگیری از تشخیص قطعی، تجویز یا قطع دارو، و وعده درمان.
3. مسیرهای ارجاع برای خطر فوری، خودآسیبی، خشونت، علائم شدید و موارد خارج از صلاحیت.
4. نسخه‌گذاری محتوا، منابع علمی و قواعد تصمیم‌گیری.
5. آزمون پاسخ‌های خطرناک، سوگیری، توهم و ارجاع نادرست.

### P2 — کیفیت محصول
1. همگام‌سازی اختیاری و امن بین دستگاه‌ها.
2. پایش پیشرفت با تفکیک تجربه ذهنی، رفتار و عملکرد روزمره.
3. دسترس‌پذیری، عملکرد، ثبت خطا و تحلیل محصول با حداقل‌سازی داده.

## ۴. جمع‌بندی

پیشنهاد فعلی، بازنویسی کامل اپ نیست. هسته React/Vite، مسیر ۲۸ روزه و کتابخانه باید تا زمان اثبات نیاز فنی حفظ شوند. دستیار هوشمند باید به‌صورت لایه‌های مستقل و قابل آزمون به محصول افزوده شود. هیچ ادعای سازگاری نهایی با بک‌اند یا سرویس ابری خاصی تا پایان ممیزی مخزن و زیرساخت مجاز نیست.
